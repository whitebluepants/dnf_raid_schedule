# 团队排表工具 V1 完整可用化设计

## 目标

把现有的认证、空间和排表算法骨架补齐为可由一个固定团体日常使用的首版：团员维护角色并报名，空间管理员创建多波活动、生成初稿、手动调整并发布。

## 已确认的产品决定

- 登录只展示昵称和密码；`蓝`是首个平台注册管理员。
- 数据以空间为边界。当前空间必须由服务端可信的 cookie 保存，所有数据查询和写入均再次验证成员身份，不能只依赖客户端参数。
- 角色、账号、活动、报名、难度配置及排表均归属一个空间。
- 空间创建者默认是空间管理员。平台管理员可将任意空间的普通成员设为或降为该空间管理员。
- 角色权限只有三种：`member`、`admin`（空间内）以及平台管理员（跨空间）。旧的 `leader` 视为可管理活动和排表的兼容角色，但新界面不再单独授予它。
- 邀请码由服务器生成可读、不可预测的唯一代码；创建者不再输入邀请码。成员加入后才能在空间内看到邀请码。

## 架构

`profiles` 新增 `is_platform_admin`。数据库 RPC 负责首个管理员初始化、空间邀请码生成、空间切换权限检查和空间成员角色变更；RLS 把平台管理员作为跨空间管理者，同时保留成员自身资料维护范围。Next.js Server Action 只接收验证过的表单数据，并从 cookie 中读取当前空间。

路由继续保持现有简洁地址（`/roster`、`/activities`），但未选择空间时会引导至 `/spaces`。页面使用真实 Supabase 查询数据；需要交互的区域采用客户端组件和 Server Action，提交后 `router.refresh()` 获取服务器最终状态。

## V1 流程

1. 注册／登录后进入空间页，创建或加入空间并选择当前空间。
2. 团员在“我的角色”里添加游戏账号和角色，填写 C/奶、名望、档位、模拟伤害或奶量。
3. 空间管理员创建活动和各波难度；团员进入报名页勾选可用角色。
4. 管理员在活动页生成可编辑初稿，在工作台内通过点击候补与槽位来放置、交换或移回候补，保存草稿并发布。
5. 管理员可标记报名成员缺席，重新生成或手动补位；发布后所有空间成员查看同一结果。

## 取舍

- 本次首版使用可靠的“点击候补 → 点击槽位”交互；原设计中的桌面拖拽会作为后续体验增强，避免用未验证的拖拽库阻塞实际排表。
- 实时订阅保留为刷新提示；写入正确性由数据库版本号、事务和唯一约束保证。
- 不实现精确到场时间、第三方登录、职业平衡或客户端数据导入，这些仍属于原设计的后续范围。
